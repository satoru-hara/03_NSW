# HNS Category Design Rationale  
### Why HNS‑36 and HNS‑144 Use Different Category Systems  
Satoru Hara, Natural Structure Works (NSW)  
May 2026

---

## 1. Overview

The Human Natural Structure (HNS) framework consists of two independent coordinate systems:

1. **HNS‑36 Foundational Specification**  
   – Defines the *structural coordinate system* (Layers × Categories).

2. **HNS‑144 Observational Specification**  
   – Defines the *observational coordinate system* for analyzing AI outputs.

Although both systems use six categories, their category names and functions differ by design.  
This document explains the rationale behind this separation.

---

## 2. Functional Difference Between the Two Category Systems

### 2.1 HNS‑36 Categories (Structural Explanatory Axes)

HNS‑36 uses the following six Categories:

- Civilization  
- Core  
- Module  
- Application  
- System  
- External  

These are **explanatory lenses** used to interpret the structural meaning of a phenomenon.  
They answer the question:

> **“How should this phenomenon be explained structurally?”**

### 2.2 HNS‑144 Categories (Observational Attribute Axes)

HNS‑144 uses a different set of six Categories:

- Identity  
- Function  
- State  
- Relation  
- Value  
- Context  

These are **observational attributes** used to describe what is detected in AI outputs.  
They answer the question:

> **“What is being observed?”**

---

## 3. Why the Category Names Must Differ

### 3.1 Different Purposes Require Different Conceptual Axes

- HNS‑36 describes **the structure of the world**.  
- HNS‑144 describes **the observation of AI behavior**.

Using identical category names would conflate:

- structure and observation  
- explanation and detection  
- ontology and measurement  

This would violate the independence required for external verification.

### 3.2 Avoiding Circular Definitions

If both systems used the same category names:

- structural meaning would depend on observational attributes  
- observational results would redefine structural coordinates  

This creates circularity and invalidates the specification.

### 3.3 ISO/IEC Requirements for Conceptual Independence

International standards require:

- non-overlapping conceptual domains  
- clear normative boundaries  
- independent coordinate systems  

The separation of category names satisfies these requirements.

---

## 4. Orthogonality Between Structure and Observation

The two category systems are **orthogonal**:

- HNS‑36 → structural coordinate system  
- HNS‑144 → observational coordinate system  

Orthogonality ensures:

- structural positions remain stable  
- observational results remain interpretable  
- EVA (External Verification Architecture) can operate independently of model internals

---

## 5. Correspondence Table (Non-normative)

Although the two systems are independent, the following table shows how structural meaning tends to appear in observation:

| HNS‑36 Category | HNS‑144 Category | Correspondence (Interpretive) |
|-----------------|------------------|-------------------------------|
| Civilization | Context | Macro-scale structures appear as broad context |
| Core | Identity | Essential structure appears as identity attributes |
| Module | Function / State | Components appear as functions or states |
| Application | Value / Function | Applied purpose appears as value or use |
| System | Relation / Function | Mechanisms appear as relations and processes |
| External | Context / Relation | External structures appear as contextual relations |

This table is **non-normative** and provided only for interpretive clarity.

---

## 6. Conclusion

The category names differ because:

- HNS‑36 and HNS‑144 serve different conceptual purposes  
- structural and observational layers must remain independent  
- orthogonality is required for EVA and for international standardization  
- identical names would cause conceptual conflation and circularity  

The separation is therefore **intentional, necessary, and foundational** to the HNS framework.
